# Data dictionary: `drum_scans_raw.csv`

Simulated export of a data logger on a dry magnetic drum separator, with a line laser looking at the drum shell. The file is generated by `src/simulate_drum_scans.py` (seed 42). All dimensions and rates are generic teaching values, not taken from any manufacturer.

The file has 34,055 rows and 17 columns and covers 2 February to 1 June 2026. It is written with `sep=";"` and `decimal=","`. One row is one laser profile, summarised, logged every 5 minutes in local time (Europe/Vienna).

## Machine and sensor (assumed)

| Item | Value |
|---|---|
| Drum diameter | 1200 mm |
| Shell | austenitic stainless steel, 6.0 mm thick when new |
| Laser stand-off | 250 mm to a new shell at 20 °C, mounted on a 250 mm steel bracket |
| Laser | line laser across the drum width; the profile is summarised as a mean and a maximum distance |

## Columns

| Column | Unit | Meaning |
|---|---|---|
| `timestamp` | local time | Time of the scan |
| `scan_id` | – | Logger counter, one number per scan |
| `operating_hours` | h | PLC hour counter of the machine; counts only while the drum runs |
| `ore_type` | – | Feed campaign: `fine`, `coarse` or `slag` |
| `drum_speed_rpm` | rpm | Drum speed; 0 = stopped |
| `feed_rate_t_h` | t/h | Feed rate onto the drum |
| `ambient_temp_c` | °C | Hall temperature near the laser bracket |
| `shell_temp_c` | °C | Shell surface temperature (infrared thermometer) |
| `humidity_pct` | % RH | Relative humidity, as sent by the sensor |
| `vibration_rms_mm_s` | mm/s | Vibration velocity RMS on the laser bracket |
| `drum_angle_deg` | ° | Encoder angle of the drum at the moment of the scan |
| `laser_intensity` | counts | Mean reflected intensity of the profile |
| `valid_points_pct` | % | Share of profile points the laser could measure |
| `dist_mean_mm` | mm | Mean distance from the laser to the shell surface across the width |
| `dist_max_mm` | mm | Largest distance across the width, i.e. the deepest wear groove |
| `ut_ref_thickness_mm` | mm | Manual ultrasonic gauge reading, taken once per planned maintenance (otherwise empty) |
| `sim_true_min_thickness_mm` | mm | **Target.** True minimum shell thickness, known only because the data is simulated |

**How the laser relates to thickness.** As the shell wears, its outer surface moves away from the laser, so the distance grows. The largest distance (`dist_max_mm`) belongs to the thinnest point of the shell. In a real plant the target column would not exist; here it lets you check how well your cleaning recovers the true wear.

## Physics in the simulation

- **Wear (Archard-type law).** The wear rate is proportional to ore abrasiveness, feed rate and drum speed, so it is roughly 0.04 to 0.10 mm per 100 running hours. There is no wear while the drum stands still or runs empty.
- **Geometry.** The drum has eccentricity (0.10 mm run-out) and an oval shell (0.035 mm). Both depend on `drum_angle_deg`.
- **Temperature.** The rotating shell is warmed by eddy currents. A warm shell expands towards the laser, and a warm bracket moves the laser towards the shell; both shorten the measured distance. The laser was zeroed at 20 °C.

## Things you will find

This file is meant to be cleaned. It contains the kinds of problems a real logger export has:

- missing values coded in more than one way
- rows that are missing or repeated
- timestamps in more than one format
- values stored as text
- a sensor that sometimes freezes
- a unit that is not always what the column name says
- steps, drifts, spikes, and periods of dirty or wet measurement

Write checks (`assert`, masks, plots) that find them before you look at the answer key.

**Answer key:** `data/simulation_truth/simulation_events.csv` lists every injected event with its start and end time.

## Notes for the ML sessions (7–10)

- **Do not use the target, or anything made from it, as a feature.** `sim_true_min_thickness_mm` is the answer. `ut_ref_thickness_mm` is the answer plus gauge noise, so it is not a feature either; use it only to check or re-calibrate the laser.
- **Predicting the thickness directly fails with a time split.** The shell only gets thinner, so with training data from February–April and test data from May, every test value is below the training range. Random Forest and XGBoost cannot predict outside the range they were trained on.
- **Predict the laser correction instead.** Use the laser error, `thickness_from_laser − sim_true_min_thickness_mm`, as the target. About 98 % of the May values fall inside the February–April range, and it is exactly the noise you want to remove (wear = measured − noise). The cleaned thickness is then the laser estimate minus the predicted error.
- **`operating_hours` is a strong feature.** Wear grows with running hours, so a model can lean on it. Keep a version without it to see what the laser and context signals add on their own.

## Reproducibility

`python src/simulate_drum_scans.py` (seed 42) gives a byte-identical file with pandas 2.2 / numpy 1.26 and pandas 3.0 / numpy 2.4.
